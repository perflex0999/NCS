# 微服务架构说明（阶段 3）

## 服务-端口-职责对照表

| 服务 | 端口 | 职责 | 核心接口 |
|------|------|------|---------|
| gateway | 8080 | API 网关：统一入口、路由、JWT 鉴权 | `/api/**` 转发 |
| user | 8081 | 用户 / 认证：登录、签发 JWT | `/api/auth/login` |
| station | 8082 | 充电站 / 设备：查询、管理 | `/api/station/**`、`/api/admin/station/**`、`/api/admin/device/**` |
| order | 8083 | 充电订单（核心交易）：开始/结束充电、订单 | `/api/charge/**`、`/api/order/**`、`/api/admin/order/**` |
| billing | 8084 | 计费 / 价格：分时段价格查询、管理 | `/api/billing/price/current`、`/api/admin/price/**` |
| fault | 8085 | 故障管理 | `/api/admin/fault/**` |
| statistics | 8086 | 数据统计 | `/api/admin/stats/**` |
| agent | 8087 | AI Agent（阶段 5 实现） | — |
| common | — | 公共模块：Result、异常、JWT、跨服务 DTO | — |

## 架构要点

1. **Spring Cloud Gateway**（8080）作为统一入口，负责路由和 JWT 鉴权。
   - 白名单：`/api/auth/login`、`/api/station/**`（浏览免登录）
   - 其余接口校验 `Authorization` 头中的 JWT，解析出 userId 后通过 `X-User-Id` 头透传给下游服务。

2. **Nacos**（注册中心 + 配置中心）：所有服务注册到 Nacos，网关通过 `lb://服务名` 做负载均衡路由，Feign 通过服务名做服务间调用。

3. **OpenFeign**：订单服务（order）通过 Feign 调用计费服务（billing）查询当前价格，体现服务间调用。

4. **Sentinel 限流**：
   - station 服务：查询类接口 `/api/station/nearby` 限流 **2000 QPS**（L3 目标）
   - order 服务：核心交易 `/api/charge/start`、`/api/charge/end` 限流 **300 QPS**（L3 目标）

5. **JWT 鉴权**：登录时 user 服务签发 JWT（HS256），网关统一校验，下游服务只信任网关透传的 `X-User-Id`，不再各自做鉴权。

## 说明（简化点，答辩时可解释）

- **共享数据库**：当前各服务共用同一个 MySQL `ncs` 库（服务按领域分表，但未做物理分库）。这是学生项目常见简化，后续可演进为「每服务独立库 + 最终一致性」。
- **设备状态一致性**：order 服务「开始充电」仍直接操作 `t_device`（共享库 + Redis 分布式锁 + 数据库 CAS），保证同一设备不能重复充电。纯微服务下这需要 order 通过 Feign 调用 station 服务完成，属后续优化。
- **配置中心**：Nacos 配置通过 `spring.config.import=optional:nacos:...` 引入，配置缺失时不阻断启动（降级用本地 yml）。

## 启动方式

需先启动 Nacos（`docker compose up -d nacos` 或独立部署），再依次启动各服务：

```bash
# 网关
java -jar gateway/target/ncs-gateway-1.0.0.jar
# 各业务服务（user/station/order/billing/fault/statistics）
java -jar order/target/ncs-order-1.0.0.jar
...
```

前端通过网关访问：`http://localhost:8080/api/...`（或部署时 nginx 反代到 8080）。
